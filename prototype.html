What replaced subpixel rendering

Text rendering used to feel like a browser footnote. You picked a typeface, set a size, and hoped the operating system made reasonable decisions. That model is too simple now. Variable fonts, high density screens, GPU compositing, and browser-specific antialiasing choices all change how a line of text actually lands on the page.

The important shift is that perceived sharpness is no longer only about subpixels. It is about font metrics, contrast, layout stability, and whether the browser can keep text on a predictable compositing path.

Measure The Layout First

Before changing typefaces or hinting strategies, check whether text is being measured consistently. A surprising number of typography bugs are really layout bugs: late font swaps, mismatched fallback metrics, or containers that shift after hydration.

javascript 
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (entry.entryType === 'layout-shift') {
      console.log(entry.value, entry.sources);
    }
  }
});

observer.observe({ type: 'layout-shift', buffered: true });

Prefer Stable Metrics

The best typography systems keep fallback and final font metrics close enough that the page does not visibly reflow. That single constraint often does more for perceived polish than chasing a particular antialiasing behavior.
